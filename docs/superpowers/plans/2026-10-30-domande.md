# Parte A – Specifica

## Obiettivo

In cima alla scheda **Statistiche** un riquadro "Fai una domanda": l'utente scrive in italiano ("qual è l'ora in cui esco di più?", "in quale giornata ho fatto più interventi?", "durata media per mezzo nel 2025", "più rossi quest'anno o l'anno scorso?") e l'app risponde con i numeri del proprio archivio.

Criteri di riuscita:

- la domanda scritta diventa una query strutturata tramite Claude; **nessun record esce dal telefono**: partono solo il testo della domanda, i valori delle liste delle Impostazioni e l'elenco dei comuni distinti presenti in archivio;
- la query è eseguita sul dispositivo da codice puro e testato (`js/core/domande.js`), con gli stessi filtri di periodo e la stessa definizione di intervento delle Statistiche;
- la risposta mostra la cifra, come è stata intesa la domanda e il periodo, e sotto la classifica o la tabella;
- senza rete il riquadro è disattivato e spiega perché; il resto dell'app resta offline come oggi;
- la chiamata è protetta da una parola d'ordine; chiave Anthropic e parola d'ordine sono segreti Cloudflare, mai nel codice né nel repository.

## Scelte confermate (2026-10-30)

1. **Comprensione in cloud, dati in locale.** Claude traduce la domanda in query JSON; il calcolo avviene sul telefono.
2. **Protezione: parola d'ordine** scritta una volta nelle Impostazioni (salvata in `meta.parolaOrdineDomande`), inviata con ogni richiesta, confrontata dal Worker con il segreto `PAROLA_ORDINE`. Tetto di spesa mensile sull'account Anthropic come rete di sicurezza (lo imposta l'utente nella console Anthropic).
3. **Posizione: in cima alle Statistiche**, sopra il selettore del periodo. Nessuna scheda in più.
4. **Periodo:** se la domanda nomina un periodo vale quello; altrimenti vale il periodo selezionato nelle Statistiche. La risposta dice sempre su quale periodo è calcolata.
5. **La risposta la scrive l'app** dai numeri, in forma fissa. Una sola chiamata all'AI per domanda (più l'eventuale controdomanda).
6. **Nessuno storico:** ogni domanda è nuova; non si salva nulla della domanda o della risposta.
7. **Modello:** Haiku 5.5 (`claude-haiku-5-5`); se la risposta non è un JSON valido rispetto allo schema, il Worker riprova una volta con Sonnet 5.5 (`claude-sonnet-5-5`).
8. **Repertorio ampio:** misura × uno o due raggruppamenti × filtri (periodo, valore di lista, intervallo numerico), confronto tra due periodi, massimo/minimo/primi N.
9. **Con la domanda partono** i valori delle liste delle Impostazioni e i comuni distinti dell'archivio (normalizzati). Nient'altro.
10. **Ambiguità: controdomanda.** Claude può rispondere con una domanda di chiarimento; l'utente risponde nello stesso riquadro; al massimo una controdomanda per domanda, poi la seconda risposta deve essere una query o un rifiuto.

## 1. La query (contratto tra Worker e app)

Oggetto JSON restituito da Claude, validato dal Worker **e** dall'app (`validaQuery`). Tre forme:

```json
{ "tipo": "query", "interpretazione": "Interventi per ora del giorno", "misura": "...", "gruppi": [], "filtri": [], "periodo": null, "confronto": null, "ordine": "max", "primi": 1 }
{ "tipo": "controdomanda", "testo": "Intendi l'ora di allertamento o quella di libero operativo?" }
{ "tipo": "rifiuto", "testo": "Non posso rispondere con i dati dell'app.", "esempi": ["...", "...", "..."] }
```

Campi di `tipo: "query"`:

| Campo | Valori | Note |
|---|---|---|
| `interpretazione` | testo breve in italiano | mostrato all'utente: "Inteso come: …" |
| `misura` | `interventi`, `valutati`, `trasportati`, `durataMedia`, `durataMediana`, `durataMax`, `etaMedia`, `etaMediana`, `pctTotali`, `pctValutati` | definizioni identiche a `calcolaStatistiche`: valutati = totali − "Annullato da CO" − "Non Raggiungibile"; durata da `calcolati(r).durata`; età solo numerica. `pctTotali`/`pctValutati` = interventi del gruppo / base, frazione 0–1 |
| `gruppi` | array di 0, 1 o 2 tra: `ora`, `giornoSettimana`, `giorno`, `mese`, `anno`, `comune`, `mezzo`, `tipologia`, `codiceInvio`, `codiceRientro`, `patologiaInvio`, `patologiaRientro`, `luogoInvio`, `luogoRientro`, `esito`, `ospedale`, `fasciaEta`, `sesso`, `tipoMissione` | `ora` = `calcolati(r).ora` (0–23, etichetta "08"); `giornoSettimana` lun…dom dalla DATA; `giorno` = DATA `AAAA-MM-GG`; `mese` = `AAAA-MM`; `anno` = `AAAA`; `fasciaEta` = `FASCE_ETA` di statistiche.js; `comune` confrontato con `normalizzaTesto` |
| `filtri` | array di `{ "campo", "op", "valore" }` | `campo`: una chiave di `CAMPI` oppure `durata`, `ora`, `giornoSettimana`; `op`: `=`, `!=`, `>`, `>=`, `<`, `<=`, `in` (valore = array). Per `comune` il confronto usa `normalizzaTesto` |
| `periodo` | `null` oppure `{ tipo: 'anno', anno }`, `{ tipo: 'mese', anno, mese }`, `{ tipo: 'intervallo', da, a }`, `{ tipo: 'tutto' }` | `null` = usa il periodo selezionato nelle Statistiche |
| `confronto` | `null` oppure `{ "periodoA": periodo, "periodoB": periodo }` | con `confronto` il campo `periodo` è ignorato; `gruppi` deve essere `[]` |
| `ordine` | `max`, `min`, `nessuno` | per `gruppi` non vuoti: ordina per valore della misura |
| `primi` | intero 1–50 oppure `null` | `null` = tutta la classifica. In testa si evidenzia il primo gruppo secondo `ordine` |

Regole di validità (`validaQuery` restituisce `{ ok: true, query }` oppure `{ ok: false, motivo }`): tipi come da tabella, nessun campo sconosciuto, `gruppi` senza ripetizioni, `confronto` solo con `gruppi: []`, `op` numerici solo su `eta`, `tempoVolo`, `durata`, `ora`; `in` solo con array non vuoto; date `AAAA-MM-GG` valide (`isDataValida`), mese 1–12.

Date relative ("quest'anno", "il mese scorso", "ultimi 30 giorni") le risolve Claude: il Worker passa nel prompt la data odierna ricevuta dall'app (`oggi`, `AAAA-MM-GG`, fuso del dispositivo).

## 2. Esecuzione sul dispositivo (`js/core/domande.js`)

`eseguiQuery(records, liste, query, periodoPagina)` → risultato:

```json
{ "periodo": { "tipo": "anno", "anno": 2026 }, "descrizionePeriodo": "Anno 2026", "base": 212,
  "righe": [ { "chiavi": ["18"], "etichette": ["Ore 18"], "valore": 23, "n": 23 } ],
  "colonne": null, "evidenziata": 0, "confronto": null, "misura": "interventi" }
```

- Selezione: `filtraPeriodo(records, query.periodo ?? periodoPagina)`, poi i `filtri`. `base` = righe selezionate dopo i filtri.
- `gruppi: []` → una sola riga con `chiavi: []`, `valore` = misura su tutta la selezione.
- Un gruppo → una riga per valore presente (ora/giornoSettimana/fasciaEta: tutti i valori possibili, anche a zero; `giorno`/`mese`/`anno`/liste: solo quelli presenti, le voci di lista nell'ordine della lista con `vociTabella`). Righe ordinate secondo `ordine` (a parità: ordine naturale della chiave), tagliate a `primi`.
- Due gruppi → `righe` = valori del primo gruppo, `colonne` = valori del secondo, ogni riga ha `celle: { [colonna]: valore }` e `valore` = misura sulla riga intera; `ordine`/`primi` sulle righe.
- `confronto` → `righe: []`, `confronto: { a: { descrizionePeriodo, valore, n }, b: {…}, differenza, variazionePct }` (`variazionePct` null se `a.valore` è 0 o null).
- Misure su gruppi vuoti: conteggi 0, medie/mediane/max `null`.
- Le righe senza DATA contano solo con periodo `tutto` (come le Statistiche); per `giorno`, `mese`, `anno`, `giornoSettimana` finiscono nel gruppo `—` ("Senza data") solo se `ordine === 'nessuno'`, altrimenti escluse.

`descriviPeriodo(periodo)` riusa la logica di `descrizione` oggi dentro `js/ui/statistiche.js`: spostarla in `js/core/domande.js` come `descriviPeriodo` e farla importare dalla UI.

`normalizzaTesto(t)`: minuscole, senza accenti (NFD, tolti i segni), spazi compressi, trim. `comuniDistinti(records)`: comuni non vuoti degli interventi, deduplicati su `normalizzaTesto`, ordinati, tenendo la prima grafia incontrata.

## 3. Il Worker (`worker/domande.js`)

Lo stesso Worker `liberoeoperativo` che oggi serve i file statici. `wrangler deploy` passa a un file di configurazione minimo scritto dallo script di pubblicazione nella cartella temporanea:

```jsonc
{ "name": "liberoeoperativo", "main": "domande.js", "compatibility_date": "2026-10-23",
  "assets": { "directory": "./site", "binding": "ASSETS" } }
```

Comportamento di `fetch(richiesta, env)`:

- Tutto ciò che non è `POST /api/domanda` → `env.ASSETS.fetch(richiesta)` (i file statici come oggi, 404 compresi).
- `POST /api/domanda`, corpo JSON `{ parolaOrdine, domanda, oggi, liste, comuni, controdomanda?: { testo, risposta } }`:
  - parola mancante o diversa da `env.PAROLA_ORDINE` → `401 { errore: 'Parola d\'ordine errata.' }`; confronto a tempo costante (`crypto.subtle.timingSafeEqual` su buffer di pari lunghezza, altrimenti falso);
  - `domanda` vuota o oltre 500 caratteri, `liste` o `comuni` oltre 2000 voci → `400`;
  - chiama l'API Anthropic (`POST https://api.anthropic.com/v1/messages`, header `x-api-key: env.CHIAVE_ANTHROPIC`, `anthropic-version: 2023-06-01`), modello `claude-haiku-5-5`, `max_tokens: 600`, system prompt = `PROMPT_SISTEMA` (sotto) + valori delle liste + comuni + `oggi`; messaggio utente = la domanda; con `controdomanda` presente, il messaggio include domanda, controdomanda e risposta dell'utente e il prompt vieta un'altra controdomanda;
  - estrae il primo oggetto JSON dal testo di risposta, `validaQuery` (stesso modulo condiviso: il Worker importa `../js/core/domande.js`); se non valido → riprova una volta con `claude-sonnet-5-5`; se ancora non valido → `502 { errore: 'Non sono riuscito a tradurre la domanda.' }`;
  - risposta `200` con l'oggetto validato (`tipo` query/controdomanda/rifiuto) e `modello` usato.
- Nessun log del testo della domanda. Timeout 20 s verso Anthropic → `504`. Errore Anthropic (429, 5xx) → `502` con messaggio generico in italiano.
- `PROMPT_SISTEMA` (costante esportata, in italiano): spiega il dominio (archivio personale di missioni 118: campi di `CAMPI` con una riga di significato ciascuno, codici VERDE<GIALLO<ROSSO, NERO solo al rientro, India/Mike, elicotteri), il contratto JSON della sezione 1 con l'elenco esatto dei valori ammessi, le regole (rispondere **solo** con un JSON; `interpretazione` breve; periodo `null` se non nominato; date relative risolte con `oggi`; se la domanda è fuori perimetro → `rifiuto` con 3 `esempi` vicini a ciò che l'utente ha scritto; se ambigua in modo che cambia il risultato → `controdomanda`, mai più di una; ospedali, patologie, luoghi, mezzi, esiti vanno scelti tra i valori forniti, i comuni tra quelli forniti se somigliano, altrimenti come scritti).

Segreti Cloudflare, impostati dall'utente una volta (dalla cartella temporanea o con `--name`, mai dalla cartella del progetto):

```bash
npx --yes wrangler@4.156.0 secret put CHIAVE_ANTHROPIC --name liberoeoperativo
```


- Risposta `controdomanda` → sotto il campo compare la domanda di Claude e un secondo campo "Risposta" con bottone "Rispondi"; l'invio ripete la chiamata con `controdomanda: { testo, risposta }`.
- Risposta `rifiuto` → testo + i 3 esempi come chip.
- Risposta `query` → `eseguiQuery(stato.record, stato.liste, query, periodo)` e `disegnaRisposta(risultato, query)`:
  - cifra grande (`.valore`) formattata per misura: conteggi con `conteggio`, durate con `oreMinuti`, età con `numero`, percentuali con `pct`; con gruppi: etichetta del gruppo evidenziato + cifra ("Ore 18 · 23 interventi");
  - riga `.nota`: "Inteso come: {interpretazione} · {descrizionePeriodo} · su {base} interventi";

  - confronto: due caselle KPI (`voceKpi`) affiancate con i due periodi e sotto "Differenza: +N (+12%)".
- Errori HTTP: 401 → "Parola d'ordine errata: controlla le Impostazioni."; altri → messaggio dell'errore o "Non riesco a contattare il servizio. Riprova."; mostrati in `.avviso` sotto il campo, mai come toast (restano leggibili).
- Nessuna persistenza della domanda o della risposta (scelta 6). Il periodo della pagina resta quello scelto: la domanda non lo cambia.
